## 产品概述

在 `dataset_query` 工具的结果表格卡片上新增「导出」能力：把本次查询的完整结果导出成本地 CSV 文件。

## 核心功能

- **导出按钮**：只在有视图的表格卡片（`meta.kind === 'dataset-view'`）底部工具条出现；无视图时卡片退化为纯文本的场景不提供导出。
- **全量导出，不做分页限制**：点击后自动按 `pageSize = maxPageSize` 逐页顺序拉取，直到服务端给出的末页，拼装为完整 CSV 后一次性下载；不受当前所在页码与每页展示行数影响。
- **跟随当前排序**：导出使用表格当前的排序列与升降序，导出内容与用户在界面上看到的行顺序一致。
- **CSV 格式**：UTF-8 带 BOM，Excel 双击直接打开不乱码；单元格含逗号/引号/换行时正确转义，对以 `= + - @` 开头的单元格做防公式注入处理。
- **过程反馈与错误处理**：导出期间按钮禁用并显示「导出中…（已取 x / 共 y 行）」；视图过期提示「结果已过期，请重新查询」，其它失败给出「导出失败（HTTP xxx）」；切换排序或重新取数时中止进行中的导出。

## 技术栈

- 沿用项目现有技术栈：React（external seed 词，运行时由平台模块表提供）+ TypeScript，浏览器半身由 `tsdown` 打包为 CJS 工厂（`window.__ModuleLoader__.load`），**不引入任何新依赖**。
- 仅修改 `src/client/index.ts`；服务端（`src/view.ts` / `src/http.ts` / `src/index.ts` 配置）与降级纯文本分支均不动。

## 实现方案

**策略**：纯客户端循环分页导出。复用卡片已有的 `GET {endpoint}?page&pageSize&sort&order` 取数通道，把 `pageSize` 提到 `meta.maxPageSize`（默认 500），顺序拉取第 1 页到 `totalPages` 页，边拉边把每行转成 CSV 分片，最后拼 BOM 一次性 Blob 下载。

**关键技术决策**

- **不新增服务端端点**：用户明确选择最小改动；代价是导出上限仍是服务端可服务行数 `servableRows = min(totalRows, rowCap, maxViewRows)`（默认 5 万），属于「不受分页限制、但受视图硬上限约束」，与卡片上已展示的「仅可浏览前 N 行」口径一致。
- **顺序请求而非并发**：视图每次翻页都重新执行 SQL，并发会打爆本地数据库与连接池；顺序串行最稳，5 万行 / 500 每页 = 100 次请求，单页响应在毫秒级，整体可接受。
- **分片拼装而非全量行对象驻留**：每页转成字符串分片后即丢弃行对象，避免 5 万行 JSON 对象同时常驻内存（峰值约为最终 CSV 文本大小 + 单页对象），`Blob` 构造放在最后一步。
- **只导出表格当前列集合**：沿用 `payload.columns`（与表头一致，通常含 `_row_id`），不额外裁剪，避免与界面显示不一致。
- **导出与浏览解耦**：导出使用独立的 `AbortController` 与独立状态，不复用分页的 `requestId` 竞态保护，避免导出进度与翻页请求互相干扰。

**性能与可靠性**

- 时间复杂度 O(总行数 × 列数)，瓶颈在网络往返与 `JSON.parse`；通过 `pageSize` 顶到 `maxPageSize` 把请求次数压到 `ceil(servableRows / maxPageSize)`。
- 每页更新一次进度会触发重渲染：仅更新 `{ done, total }` 两个数字，成本可控；若担心高频重渲染可在页内累积、每 N 页刷新一次（本次保持简单，每页刷新）。
- 卸载 / 排序变更 / 取数重启时 `abort()` 进行中的导出，避免悬垂请求与内存泄漏。

## 实现要点（落地细节）

- 新增纯函数 `toCsvCell(value)` / `toCsv(columns, rows)`：复用现有 `formatCell`；命中 `"` `,` `\n` `\r` 时加双引号并把 `"` 转成 `""`；以 `= + - @` 开头加 `'` 前缀；行分隔用 `\r\n`。
- 新增 `downloadCsv(filename, text)`：`\uFEFF` BOM + `new Blob([text], { type: 'text/csv;charset=utf-8' })` + `URL.createObjectURL` + 临时 `<a download>` 点击 + `URL.revokeObjectURL`；文件名 `数据集名-YYYYMMDD-HHmmss.csv`，清理 `\/:*?"<>|` 等非法字符。
- 卡片新增状态：`exporting: boolean`、`progress: { done: number; total: number } | undefined`、`exportError?: string`，以及 `exportAbort = useRef<AbortController | undefined>(undefined)`；`useEffect(() => () => exportAbort.current?.abort(), [])` 负责卸载清理。
- `exportCsv` 回调（`useCallback`，依赖 `meta` / `sort`）：

1. `const pageSize = Math.max(1, meta.maxPageSize > 0 ? meta.maxPageSize : meta.pageSize)`；
2. 拼 URL 时带上当前 `sort.column` / `sort.order`（与现有取数 effect 完全一致的拼参方式）；
3. 先取第 1 页，用返回的 `columns` 与 `totalPages` 作为导出基准；
4. `for (page = 2; page <= totalPages; page++)` 顺序拉取，每页完成后 `setProgress({ done: 累计行数, total: totalRows })`；
5. 每次请求检查 `controller.signal.aborted` 与 `response.ok`，错误文案沿用现有风格：404 / `VIEW_NOT_FOUND` → '结果已过期，请重新查询'，其余 → `导出失败（HTTP ${status}）`，网络异常 → `导出失败：${error}`，abort 静默返回；
6. 结束后 `downloadCsv(...)` 并清空进度与错误。

- UI 变更：在 `styles.bar` 工具条内追加「导出 CSV」按钮（`type="button"`，`disabled = exporting || state.status === 'error'`，导出中显示「导出中…（x/y 行）」）；新增导出失败的 `styles.error` 提示；按钮 `title` 说明最多导出可浏览行数（`servableRows`）。
- 不因 `meta.stable === false` 禁用导出（不稳定排序只限制逐页浏览）。

## 架构设计

改动完全收敛在浏览器半身的单个组件内，不触碰服务端与工具契约：

```mermaid
flowchart TD
    A[用户点击 导出 CSV] --> B[exportCsv: 建立 AbortController]
    B --> C[GET endpoint?page=1&pageSize=maxPageSize&sort&order]
    C --> D[得到 columns / totalPages / rows]
    D --> E[第 1 页转 CSV 分片]
    E --> F{page < totalPages?}
    F -- 是 --> G[page+1 继续取数并追加分片 + 更新进度]
    G --> F
    F -- 否 --> H[拼 BOM + Blob]
    H --> I[临时 a[download] 触发浏览器下载]
    B -. 卸载 / 排序变更 .-> J[abort 进行中的导出]
```
