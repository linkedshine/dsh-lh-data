# 设计文档：`dsh-lh-data` 查询结果视图化（模型只拿片段，前端分页取数）

> 版本：v1（草案）
> 关联：插件设计文档 [`docs/excel-to-turso-skill设计.md`](excel-to-turso-skill设计.md)
> 平台：`D:\fastwork\projects\node\deepseek-harness`（下称 dsh）
> 目标：`dataset_query` 命中大数据集时，**只把精简片段交给大模型**；完整结果以「服务端视图句柄 + 分页 SQL」的形式交给前端，由前端自动拉取并渲染表格。

---

## 1. 背景与问题

现状：

- `dataset_query` 的 `execute` 把查询结果整包作为规范 JSON 值返回，`output.render` 再渲染成 markdown 表格喂给模型（`src/tools/read.ts:225-268`）。
- 上限只有 `maxQueryRows`（默认 200）。即使这样，200 行 × 几十列也可能有几万字符，全部进入会话历史：
  - 挤占上下文、抬高成本；
  - 模型为了「看数据」而反复翻页调用，每页都进历史，问题放大；
  - 平台侧**不会自动裁剪**（spill-policy 默认未启用，工具结果原样落盘），所以「返回多少就占多少」。
- 用户真正需要的是**看全量数据**（人眼浏览、排序、导出），模型只需要**足够下结论的摘要**。

结论：需要把「给模型的内容」与「给人看的数据」拆成两条通道。

---

## 2. 目标与非目标

### 2.1 目标

1. **模型侧只拿片段**：默认返回结果摘要 + 少量预览行（可控字节上限），不再整包入上下文。
2. **人侧拿全量**：完整结果以只读视图暴露给前端，支持翻页、排序、按列密度自适应渲染。
3. **句柄化不破坏**：模型仍只见 `datasetId` / 登记名；物理表名与 SQL **不出主机**。
4. **零前端侵入**：前端能力由插件自带（client half），不改 dsh 内核。
5. **优雅降级**：无浏览器剖面（CLI / TUI）、无 `webServer`、卡片加载失败，退化为当前的文本表格输出；视图接口不可用时前端提示「数据接口不可用」而非清空表格。

### 2.2 非目标

- 不在前端做 SQL 编辑/执行器（前端只按 `viewId` 取页，不接受任意 SQL）。
- 不做数据写回（视图接口严格只读）。
- 不做导出（CSV/Excel 导出另立议题）。
- 不实现图表/透视（后续可复用同一视图句柄）。

## 4. 总体方案

### 4.1 架构

```text
                 ┌─────────────────────── Host（Node，插件内） ───────────────────────┐
模型 ──dataset_query──▶  execute()
                          ├─ 只读校验 + 组装 SQL（sql.ts，既有能力）
                          ├─ 执行「首屏 + 统计摘要」
                          ├─ 注册视图 → ViewRegistry（viewId → {scopeKey, countSql, pageSql, columns…}）
                          ├─ output.render        ──▶ 精简片段（进上下文）
                          └─ output.presentationMeta ─▶ { kind:'dataset-view', viewId, endpoint, … }
                                                             │  （不进上下文）
                                                             ▼
前端卡片 ◀──meta── 工具结果节点 ─────────────────────────────────┘
   │
   └── fetch GET {endpoint}?page=2&pageSize=100
              │
              ▼
        webServer 路由（/api/lh-data/views/:id/rows）
              ├─ connection.requestRejection(req) → 401/403
              ├─ ViewRegistry.get(viewId) → 404（未注册）
              └─ 复用已校验的 pageSql 执行 LIMIT/OFFSET → JSON
```

### 4.2 时序

1. 模型调用 `dataset_query`（结构化参数或原始 SQL）。
2. 插件走既有校验器得到**已校验的基础语句** `baseSql`（`validateReadOnlyQuery` / `buildStructuredQuery`）。
3. 由 `baseSql` 派生两条语句：
   - `countSql`：`SELECT COUNT(*) AS _total FROM (<baseSql，未加 LIMIT>)`
   - `pageSql`：`<baseSql，未加 LIMIT> ORDER BY <稳定排序> LIMIT ? OFFSET ?`
4. 执行一次 `LIMIT previewRows` 得到预览行，执行一次 `countSql` 得到 `totalRows`，并基于预览行 + 全列采样生成**类型化摘要**（见 §5.3）。
5. 决定是否启用视图模式（§5.2）。启用则注册视图并把描述符放进 `presentationMeta`；不启用则按现有行为内嵌全量。
6. 前端卡片拿到 `meta` 后自动拉取第 1 页并渲染；翻页/排序时只带 `viewId` 与分页参数。

> 视图**每次翻页都重新执行 SQL**（不缓存行数据），因此读到的是最新数据；排序键带 `_row_id` 兜底以保证翻页稳定。

## 5. 数据契约

### 5.1 工具输出（规范 JSON 值）

`dataset_query` 的 `output.schema` 扩展为：

```ts
interface QueryOutput {
  datasetId: string
  name: string
  columns: { name: string; type: 'text' | 'numeric' | 'boolean' | 'date' }[]
  matchedRows: number               // 实际命中的行数（不受上限收敛影响）
  totalRows: number                 // 本次可服务的行数（受 maxViewRows 限制）
  preview: {
    rows: Row[]                     // ≤ previewRows 行，单元格按 previewCellChars 截断
    cellTruncated: boolean
    columnTruncated: boolean        // 列数超过 previewColumns 时折叠
  }
  summary: ColumnSummary[]          // 见 §5.3
  limit: number
  offset: number
  truncated: boolean                // 保留旧语义：preview 是否只是结果的一部分
  view?: {                          // 仅视图模式存在
    endpoint: string                // 例如 /api/lh-data/views/vw_9f3c…/rows
    pageSize: number
    stable: boolean                 // 排序是否稳定（false 时前端禁止深翻页）
    expiresAt: number               // epoch ms
  }
}
```

**关于 `viewId` 的位置（实现后的修正）**：原计划「viewId 只出现在 `presentationMeta`」无法成立 —— 平台的 `presentationMeta` 必须是 `(args, value)` 的**纯函数**（要能重放），因此它只能从规范值派生，`viewId` 必须随规范值携带。实现取舍：

- `view.viewId` / `view.endpoint` **在规范值里**（落会话日志，模型不读）；
- `output.render` **不打印**它们 —— 模型可见文本里没有 viewId；
- 真正的安全边界不是「藏住 viewId」，而是「viewId 是不可枚举随机串 + 接口只读 + 过浏览器鉴权」。

### 5.2 视图模式的启用条件

| 配置 | 语义 |
| --- | --- |
| `viewMode: 'auto'`（默认） | `totalRows > viewThresholdRows` **或** 片段序列化字节 > `viewThresholdBytes` 时启用 |
| `viewMode: 'always'` | 只要注册成功就启用（含小结果集） |
| `viewMode: 'never'` / 无 `webServer` / 无 `connection` | 退化：不注册视图，`view` 省略，按 `maxQueryRows` 内嵌（等价今天的行为） |

### 5.3 模型可见文本（render 产物）

```
数据集 sales（ds_lz4k2a）：共 12,483 行 × 8 列，返回前 5 行预览。

| 名称 | 数量 | 单价 | 状态 | …（另有 3 列）
| 钢管 | 120 | 4.5  | 已完成 | …
…

摘要：
- 数量 numeric：min 1 / max 900 / avg 132.4 / 空 0
- 单价 numeric：min 0.8 / max 99.0 / avg 12.7 / 空 12
- 状态 text：已完成 8,231 / 待处理 3,102 / 已取消 1,150（distinct 3）
- 日期 date：2024-01-02 ~ 2026-08-30

完整结果（12,483 行）已在结果表格中展示，可翻页与排序。
若需据此下结论，请用更精确的 where 或聚合 SQL 再查一次；不要试图逐页读取全量。
```

生成规则：

- 预览行：默认 5 行（头 `ceil(n/2)` + 尾 `floor(n/2)` 在 `totalRows` 很大时更有信息量；可配置 `previewStrategy: 'head' | 'head-tail'`）。
- 单元格：超 `previewCellChars`（40）截断并置 `cellTruncated`。
- 列：超 `previewColumns`（12）只列前 12 列 + 列数。
- 摘要：numeric → min/max/avg/sum/空值数；text → distinct 数 + top 5 取值计数（超 30% distinct 则只给 distinct 数，避免把整列枚举塞进上下文）；date → min/max；boolean → true/false 计数。摘要基于**全表聚合**（`SELECT MIN/MAX/AVG/COUNT` 一次扫表），不是只看预览行。

### 5.4 `presentationMeta`（UI 专用，模型不可见）

```json
{
  "kind": "dataset-view",
  "viewId": "vw_9f3c1d2e4b5a6c7d8e9f",
  "endpoint": "/api/lh-data/views/vw_9f3c1d2e4b5a6c7d8e9f/rows",
  "datasetId": "ds_lz4k2a",
  "name": "sales",
  "columns": [{ "name": "名称", "type": "text" }, { "name": "数量", "type": "numeric" }],
  "totalRows": 12483,
  "pageSize": 100,
  "maxPageSize": 500,
  "stable": true,
  "sortable": ["名称", "数量", "单价", "状态"]
}
```

### 5.5 HTTP 分页接口

```text
GET  {prefix}/views/{viewId}/rows?page=1&pageSize=100&sort=数量&order=desc
GET  {prefix}/views/{viewId}                 # 视图元信息（列名/总数）
DELETE {prefix}/views/{viewId}               # 前端卸载卡片时主动释放（可选）
```

成功响应（`200`）：

```json
{
  "viewId": "vw_9f3c…",
  "columns": ["_row_id", "名称", "数量"],
  "rows": [{ "_row_id": 1, "名称": "钢管", "数量": 120 }],
  "page": 1,
  "pageSize": 100,
  "totalRows": 12483,
  "totalPages": 125,
  "stable": true
}
```

错误响应（统一 `{ "error": { "code": "...", "message": "..." } }`）：

| HTTP | code | 触发 |
| --- | --- | --- |
| 401 | `UNAUTHORIZED` | `connection.requestRejection` → 401 |
| 403 | `FORBIDDEN` | Host/Origin 围栏不通过 |
| 404 | `VIEW_NOT_FOUND` | viewId 未注册或接口不可用（对外统一 404，便于前端提示「数据接口不可用」） |
| 400 | `BAD_REQUEST` | page/pageSize 非法、`sort` 不在白名单、`order` 非 asc/desc |
| 405 | `METHOD_NOT_ALLOWED` | 非 GET/DELETE |
| 500 | `QUERY_FAILED` | SQL 执行异常（消息脱敏，不含物理表名） |

约束：

- `pageSize` 服务端夹紧到 `[1, maxPageSize]`；`page` 上限 `ceil(min(totalRows, maxViewRows) / pageSize)`。
- `sort` 只接受视图创建时记录的 `sortable` 列名白名单，方向 `asc` / `desc`；拼装前复用 `validateOrderBy()` 引号化。
- 每行都带 `_row_id`，前端如需定位写操作（`dataset_update` / `dataset_delete`）可直接引用。
- 路由只回答 `application/json`，`Cache-Control: no-store`。

## 6. 视图注册中心（`src/view.ts`）

```ts
interface RegisteredView {
  viewId: string
  scopeKey: string          // 创建时绑定的工作区
  datasetId: string
  tableName: string         // 仅主机持有，绝不外发
  columns: { name: string; type: ColumnType }[]
  countSql: string
  pageSql: string           // 已含 ORDER BY … LIMIT ? OFFSET ?
  totalRows: number
  sortable: string[]
  stable: boolean
  createdAt: number
}
```

- **句柄**：`viewId = 'vw_' + 24 位 base36 随机`（`crypto.randomBytes`，128 bit 量级），不可枚举、不含任何表名/列信息。
- **生命周期**：视图元数据持久化到数据库表 `lh_views`（与数据集同库、同 scope），进程重启 / 插件重载 / 热更新后仍能翻页查看，永不过期、不被容量淘汰。内存 `Map` 为热缓存，启动时由 `ViewRegistry.loadAll()` 从各 scope 库预载。
- **释放**：前端卸载卡片 / 显式 `DELETE` 时双删（内存 + 库表行）；插件卸载时 `clear()` 仅清空内存缓存，不删库表。
- **归属**：视图绑定创建时的 `scopeKey`，翻页请求复用该 `scopeKey` 重新走 `store.require()` 归属断言与 `assertPhysicalTableName()`。
- **一致性**：翻页是 fresh read，行数据在两次翻页之间可能被并发写入改变；`stable=true` 时靠 `ORDER BY … , _row_id` 保证不重复不漏读（除被删除的行）。`stable=false`（如 `GROUP BY` / `DISTINCT` / 无法补 `_row_id` 的原始 SQL）时，前端只展示第 1 页并提示「请改用带排序的查询」。

## 7. 前端卡片（client half）

### 7.1 装载方式

- `package.json` 增加：

```json
{
  "exports": { ".": { "types": "./lib/types/index.d.ts", "default": "./lib/index.js" },
               "./client": { "types": "./lib/types/client/index.d.ts", "default": "./lib/client.js" } },
  "dsh": {
    "bundle": { "patch": "./cordis.patch.yml" },
    "client": { "platform": "web", "inject": [] }
  }
}
```

- `tsdown.config.ts` 增加 client 入口（`src/client/index.tsx` → `lib/client.js`），React 走 host 的模块表基线（external），不额外请求工作区包（见 §13 风险）。
- client half 在 `tool.call.toolview` 上以 **key = `dataset_query`** 注册，接管该工具的全部调用渲染。

### 7.2 渲染与降级（重要）

由于 keyed slot 会接管**所有** `dataset_query` 调用，组件必须自己处理无视图的情况：

| `block.meta` | 渲染 |
| --- | --- |
| `{ kind: 'dataset-view' }` | 数据表格卡片：列名、行数、分页器、列排序、单元格溢出省略、加载/错误态 |
| 缺失 / 无 `view` | 退化为轻量纯文本块（等价通用行：标题 + 片段），不发起任何请求 |
| 有 `view` 但请求 404 | 表格区保留上一页数据并顶部显示「数据接口不可用」，不再清空表格 |

其他约定：

- 相对路径 `fetch`（同源），不硬编码端口；URL 直接取 `meta.endpoint`，前缀由主机侧配置决定。
- 首屏自动拉取第 1 页；滚动到底或点分页器时预取下一页。
- 卡片卸载时 `DELETE` 释放（视图已持久化，无需因过期而释放）。

## 8. 配置新增

在 `src/index.ts` 的 `Config`（schemastery）与 `src/store.ts` 的 `DataConfig` 同步增加：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `viewMode` | `'auto'` | `auto` / `always` / `never` |
| `viewThresholdRows` | `20` | 超过该行数启用视图（auto） |
| `viewThresholdBytes` | `4096` | 片段序列化超过该字节数启用视图（auto） |
| `previewRows` | `5` | 模型侧预览行数 |
| `previewStrategy` | `'head'` | `head` / `head-tail` |
| `previewCellChars` | `40` | 单元格截断长度 |
| `previewColumns` | `12` | 预览列数上限 |
| `summaryEnabled` | `true` | 是否生成列摘要 |
| `defaultPageSize` | `100` | 前端首屏页大小 |
| `maxPageSize` | `500` | 单页上限 |
| `maxViewRows` | `50000` | 一个视图可翻到的最大行数 |
| `viewRoutePrefix` | `'/api/lh-data'` | HTTP 路由前缀 |

与既有配置的关系（实现后的最终语义）：

| 场景 | 行数上限 | 说明 |
| --- | --- | --- |
| 有视图且模型未声明 `limit` | `maxViewRows`（默认 50000） | 视图可翻到全量；`maxQueryRows` 不再压制视图，否则大结果集只能翻 200 行 |
| 有视图且模型声明 `limit` | `min(limit, maxViewRows)` | 模型的显式收敛仍然生效 |
| 无视图（降级 / CLI / `never`） | `plan.rowCap = min(limit ?? 50, maxQueryRows)` | 与旧行为一致：默认 50 行，上限 200 行 |

`truncated` 的判定改为 `matchedRows > preview.rows.length`（以**真实命中数**判定，上限收敛不会把它抹掉）；`totalRows` 是本次可服务行数，两者不等时文本会写明「命中 N 行（本次可服务 M 行）」。旧行为在 `viewMode: 'never'` 下完全不变。

## 9. 安全模型

1. **句柄化不变**：模型侧、前端侧都只见 `viewId` + `datasetId`；物理表名与 SQL 只存在于主机的 `RegisteredView`。
2. **分页接口不接受 SQL**：只接受 `viewId` + 分页/排序参数，SQL 由主机从注册表取回，杜绝注入面。
3. **语句派生不新增校验漏洞**：`countSql` / `pageSql` 由**已通过 `validateReadOnlyQuery` / `buildStructuredQuery` 的基础语句**派生；派生后仍走一次同样的关键字与表引用校验（defense-in-depth）。
4. **只读**：路由只执行 `pageSql`（`SELECT`），`pre-execute` 的写门禁与 `guard()` 不涉及；`readOnly` 配置不影响只读视图。
5. **鉴权**：每个请求先过 `ctx.connection.requestRejection(req)`，401/403 直接返回，不查库。
6. **越权面（已知限制）**：HTTP 请求无法归属到具体 agent 会话，因此只要浏览器已通过主机鉴权且知道 `viewId`，就能读取该视图。缓解措施：`viewId` 为不可枚举随机串、TTL 30 分钟、LRU 容量限制、仅只读、可主动 `DELETE`；视图内容本身是「用户自己的 agent 刚查过的数据」。后续若平台暴露请求级会话身份，再补二次归属断言。
7. **日志**：分页请求只记 `viewId` 前缀、`page`、`pageSize`、耗时、行数，不记行内容与 SQL。

## 10. 兼容与迁移

- 小结果集（`viewMode: 'auto'` 且未过阈值）行为与今天完全一致：内嵌全量、无 `view`、前端走降级文本块。
- `rows` 字段改名为 `preview.rows`：**破坏性**。处理办法：`output.schema` 只声明新结构，旧字段不保留；本插件尚在 0.x，随本次改版一次性切换，并在 README 标注。
- `maxQueryRows` 不删，语义按 §8 调整。
- 无 `webServer` / 无 `connection`（CLI、TUI、Electron IPC 场景）→ `viewMode` 强制视为 `never`，装载日志给出 warn，功能不受影响。

## 13. 备选方案与取舍

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| **A. HTTP 路由 + client half 卡片**（推荐） | 自建只读路由 + `connection` 鉴权 + `tool.call.toolview` 卡片 | 静态外部插件可用；无需内核改动；能力强（大结果、排序） |
| B. 一次性内嵌全量 + 前端本地分页 | 结果整包塞进 `meta`，前端切片 | 最简单，但**没解决**上下文占用与传输体积，几千行就撞墙 |
| C. 让模型再调 `dataset_query` 翻页 | 工具本身支持 limit/offset，模型逐页读 | 每页都进上下文，问题放大；违背需求 |
| D. 改造成动态插件用 `harness.handle` + `host.call` | RPC 现成、无需 HTTP | 需重做装载形态（动态定义 + 审批），沙箱内能否用 `@libsql/client` / 定时器待验证；收益不抵成本 |
| E. SSE / WebSocket 流式推送 | 建立长连接推页 | 过度设计；webserver 升级路由能力与鉴权复用成本更高 |

## 14. 风险与未决项

1. ~~**client half 的外部依赖解析**~~ —— **已解决**：平台 seed 词（`packages/client/web/src/platform.ts`）包含 `react` 与 `@deepseek-ai/dsh-client-ui-slots`，运行时由浏览器模块表提供，构建时保持 external 即可；卡片只用基线能力（React + cordis slots），零额外工作区依赖，仅 `@types/react` 作为 devDependency。产物已核对为 CJS 工厂包。
2. **Electron 剖面（待验证）**：webserver README 指出 Electron 走 `file://` + IPC bridge，`fetch` 语义与 HTTP 剖面不同。若卡片取数失败，卡片会显示错误态并回落到文本片段；必要时在该剖面强制 `viewMode: 'never'`。
3. **COUNT 成本**：大表精确计数可能较慢。`maxViewRows` 已做上限收敛；必要时增加 `countStrategy: 'exact' | 'estimate'`（`EXPLAIN QUERY PLAN` 估算行数）开关。
4. **宽表摘要成本**：列很多时全列聚合是一次全表扫描。可加 `summaryMaxColumns`（超出只对前 N 列 +  numeric 列做摘要）。
5. **路由前缀冲突**：`viewRoutePrefix` 重复注册会抛错并使插件 fiber 失败；需在注册前 `try/catch` 并给出可操作错误信息（前缀被占用 → 改配置）。
6. **未纳入本期**：导出 CSV、前端筛选器、跨数据集连接查询的视图、视图跨会话持久化。
